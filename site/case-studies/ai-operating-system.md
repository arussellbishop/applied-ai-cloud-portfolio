# AI Operating System — governed operational workspace

**Status: PROVEN remote working model; PARTIALLY_PROVEN historical local orchestration.**

## Problem and implementation

Keep tool-assisted engineering work persistent, inspectable and under operator control across mobile and Linux sessions. The established working path is Android/Termux → private networking → SSH/tmux → a persistent Linux/Codex/Git workspace. The cloud programme records actual PR review gates, CI evidence and explicitly approved publication actions. Persistence of a terminal session is not a guarantee that every agent task survives a host failure.

An [earlier public dossier](https://github.com/arussellbishop/ai-ml-aws-portfolio/blob/a2f1e34b1b06650640d895c36d993b973b41c169/site/aios.html) records a local dashboard, central-cycle processing, scheduled work, sleep inhibition and a checksum/sample-restore backup check. Its project register recorded dashboard HTTP 200 and 11 listed user timers on 20 September 2026. This final audit reviewed those records rather than rerunning that local system. Timer inventory does not prove every schedule executes correctly.

## Architecture and judgement

An operator sets scope; tool-assisted agents work through a persistent workspace; Git, tests and evidence record outcomes; review/approval gates control consequential publication. Heavy compute and hardware workloads remain local. Source-health and connector status must be checked independently from a task labelled complete. [Diagram](https://github.com/arussellbishop/applied-ai-cloud-portfolio/blob/main/architecture/diagrams/README.md#ai-operating-system)

## Limits

General retry/idempotency guarantees, scheduler recovery after failure, complete connector authentication and independent backup recovery are not established by the accessible record. Agentic coordination is an operating model, not a claim of an independently proven general autonomous agent platform. Human authorization remained necessary for protected-main administrator merges. No fully autonomous production deployment or blanket reliability claim is made.

Next work, if separately selected, would inventory runnable orchestration source and test schedule failures/retries and recovery with explicit acceptance criteria.
